开篇

一页看懂判断标准 · 数据口径 · 覆盖矩阵

Overview

判断一个功能值不值得做、值不值得排在前面，我们不只看「有没有做完」，而是看它能不能同时回答三个问题： 店主能不能自己用起来？同行会不会主动推荐？门店能不能因此多赚钱？ 下文每个模块都会给出三段论证：为什么有必要（数据支撑的需求判断）、为什么优先级高（不做的代价与错过的窗口）、 上线后怎么验证（用哪些指标的变化证明产品方案是对的）。

免客服
简单易上手，无需客服协助
功能的价值不在「能配出来」，而在「店主和店员自己就能配出来、用起来」。 每多一次客服介入，就是一次成本、一次等待、一次信任损耗。
判断标准：不看说明书能完成主流程；配置链路短到能一次看懂；异常有自解释的提示而不是报错。
免销售
让用户有兴趣使用，并推荐给他人
好用的功能本身就是销售。当店员觉得顺手、店长觉得省心、顾客觉得专业时， 同行来问「你们用的什么系统」就是最便宜的获客。
判断标准：操作有即时正反馈；效果顾客能看见；值得被当作谈资讲给同行听。
让门店业绩提升
帮助店主多赚钱
最终要落到店主的账上：该收的钱一分不漏、该赚的毛利守住、该推的项目推得动， 并且把提成发给真正带来业绩的人。
判断标准：减少漏单与错账；主推项目可被引导；分成规则说得清、算得准、改得动。

数据口径说明

  • 外部行业数据：来自平台官方披露、券商与咨询机构、公开招聘报告与主流财经媒体报道。正文中标注来源要点，完整清单见文末「参考来源」。
  • 试点门店埋点数据：来自试点门店在真实经营中的埋点记录，覆盖不同时间范围内的开单、开卡、充值等行为（客单数、金额、次数）。用于印证「需求是否存在」「门店真实怎么用」。
  • 两者的分工：行业数据解决「这件事在行业里有多大、是不是趋势」；埋点数据解决「我们的门店是不是也这样、改完有没有变好」。
  • 口径提醒：行业数据多为第三方测算或厂商公开案例，用于判断量级与方向，不作为精确目标值；最终验收以试点门店埋点与门店实际经营指标为准。

第一章

团购核销本期唯一从 0 到 1 的新能力

Chapter 01

门店的客流入口正在从「路过」变成「线上先买券」。团购核销要解决的是最后一百米： 顾客手里已经有券了，门店能不能在收银台上把这张券变成订单、流水和业绩。 它不只是「多了一个功能」，而是把平台上的流量真正接进门店的账里—— 这也是为什么它排在四个模块的最前面：其余三个模块是把已有的做顺手，这一章是把没有的补上。

01

团购核销 · 抖音 + 美团双平台

免客服 免销售 让门店业绩提升

一句话概括：把平台的 GMV，变成门店的营收。 店员用 APP 扫一次码，完成验券、核销、开单、记业绩、进流水；抖音与美团共用同一条屏幕链，只切换文案与平台标识。

本模块能力条目（11 项）

  • 双平台扫码 / 输码验券　扫码后自动识别券类型（抖音团购券 / 美团团购券 / 次卡 / 系统优惠券 / 代金券），无相机时可输码。
  • 手工匹配消费项 + 会话记忆　券与价目无需事先映射；验券后手工选消费项，同券名再次核销自动带出上次选择。
  • 次卡核销　支持平台标准次卡，独立「本次核销次数」，按次扣减；撤销时按次恢复。
  • 核销自动开单　核销成功即生成订单，支付方式随平台显示「抖音」或「美团」，不必再手工补录一笔。
  • 业绩归属可选　默认不选、可不选；不选则订单照常生成但不计业绩。操作人与业绩归属彻底解耦。
  • 消费顾客确认　核销前必须确认「散客 / 会员」；可在确认页直接建档会员，让公域客源沉淀进私域。
  • 核销明细 / 详情 / 1 小时撤销　明细按平台分 Tab，卡内展开详情；1 小时内可撤销，撤销结果统一成页。
  • 幂等与退款态　重复扫码走幂等弹窗、不重复开单；顾客退款后内部置「已退款」，明细列表不做无谓打扰。
  • 双平台三步开通　抖音与美团相互独立：店铺认证 → 平台授权 → 门店绑定，均经汇付天下 ISV 通道完成。
  • 团购设置 · 默认核销项预填　可按「门店 + 券」预配默认消费项，核销时自动带入；多门店按 Tab 分开管理。
  • 权限门禁与异常兜底　账号未开启「收银开单」权限时拦截全部核销入口；断网 / 相机无权限 / 超时 / 验券失败均有明确承接。

抖音生活服务消费前瞻
  • 团购已经是美发门店绕不开的客流入口。抖音生活服务 2025 年支付 GMV 超 8500 亿元、同比增长 59%；在美发所属的丽人类目里，2025 年 3–8 月消费用户数同比增长 30%、团购消费金额增长 120%、行业核销规模增长 164%。（来源见文末 1 / 5）
  • 但「卖出去」不等于「收进来」。行业测算显示，抖音推送式团购的核销率只有 50–60%，美团到店为 80–90%——按前者的口径，每 100 元 GMV 里约有 40–50 元没有走到店。平台自己也已经把考核口径从 GMV 转向核销率。核销，是 GMV 变成门店营收的唯一闸门。（来源见文末 2 / 3 / 4）
  • 而门店这一端恰恰是闸门最窄的地方。行业实践普遍反映：顾客持券到店后，前台要单独登录平台后台验券，再回到收银系统手工录单；高峰期一卡壳，线上买来的精准流量就白白流失。（来源见文末 10）
  • 峰值到来时，核销能力就是接客能力。春节前美发团购订单量达去年同期 1.5 倍以上，「三八节」美发团购订单同比 +126%——这些客流已经付过钱，店里接不住就等于把 GMV 挡在门外。剑琅目前有会员卡、储值等券能力，但没有团购核销；补上它，峰值单才进得了同一本账。（来源见文末 6）

数据论证 · 为什么优先级高

  • 需求不需要被教育，它已经每天都在发生。平台侧核销规模同比 +164%，门店侧每天都在处理团购券，只是现在发生在剑琅之外。这不是「要不要做」的判断，而是「什么时候补上」的判断。
  • 一次接入覆盖两个最大入口。抖音与美团是到店团购的双寡头：一边是 2025 年支付 GMV 超 8500 亿元、同比增长 59%；另一边是核销率 80–90%、且美团丽人直播订单核销率超 80%。双平台同一条屏幕链，单点投入换双场景。（来源见文末 7）
  • 核销能力本身就是门店的流量杠杆。平台已把考核从 GMV 转向核销率，并推广「交易上翻」——到店顾客在平台完成交易，可以为门店换来额外推荐流量。门店核销越快、越顺，越接得住这些流量，这是一个会自我强化的循环。
  • 它补的是空白，不是优化。其余三个模块是「把已有的做顺手」，可以分批上线；团购核销是能力缺口的补齐，且直接决定「团购进来的客人，算不算剑琅的客人」。因此排在第一位。

门店场景

周末高峰 周六下午，顾客拿着抖音上买好的「烫染护三件套」到店。店员在 APP 里扫一下券码——系统自动识别是抖音团购券， 带出上次为这张券配好的消费项，勾上服务员工，确认核销。订单当场生成、金额进门店流水、提成落到人头上； 顾客如果是会员，顺手记进会员账下；如果还不是，确认页就能建档。 前台不用切后台、不用手工登记，整个过程十几秒。万一点错了，一小时内还能撤。
门店授权 店长第一次开通：在 APP 内完成店铺认证 → 授权抖音 / 美团账号 → 勾选要绑定的门店。 三步走完标签变「已开通」，回到团购设置把常用券的默认核销项配好。 门店侧不需要联系服务商、不需要进第三方后台，后续新店开张时按同样路径再绑一次即可。

第二章

开单结账门店最高频、最不能出错的动作

Chapter 02

开单是门店一天里发生次数最多的操作，也是店员对系统的全部印象来源。 旧流程要求「先选顾客 → 再选项目 → 配员工 → 填备注」，缺一步就开不了单； 但门店的真实情况是：新客没建档、价目表没配全、收银到一半被人叫走。 这一模块要做的，是把这三种「开不了单」的场景逐一堵上，并且让店员不用培训就能上手。

02

开单结账

免客服 免销售 让门店业绩提升

一句话概括：让收银台上的每一秒都值钱，而且不依赖培训。 开单路径要短到新员工第一天就能走完，被打断时单据不会丢，收尾时该给的凭证当场就能给。

本模块能力条目（5 项）

  • 直接收款（快捷开单）　不选顾客、不选项目、不做任何前置配置，输入金额即可结算；金额留空时按原价自动匹配最优会员权益。
  • 加购设置弹窗　加购时一次设齐数量、价格（元）、服务员工；价格可就地改，提成归属当场确定。
  • 挂单 / 取挂单　结账中断可先挂起，单据进挂单池；首页与顾客页常驻「取挂单(N)」，随时接回继续结。
  • 开单成功页　结账后给出完整收尾：打印小票、改日期、改单号、看流水、顾客签字、继续开单。
  • 顾客卡片与会员权益可见　持卡与权益默认收起、右侧展开、一行一张卡；散客按男 / 女分列，路径更短、误触更少。

行业研究报告汇编
  • 高频 × 高流动 = 学习成本会被反复支付。行业报告显示，美业相关行业人员流动率约 41%，新员工平均需要 11.3 天才熟练操作系统，误操作率约 14.2%。每多一步操作、每多一个「必须先配好才能用」的前置条件，都会在每次人员更替时重新变成培训成本和客服工单——这正是「免客服」支柱要消灭的成本。（来源见文末 11）
  • 收银台上的每一秒都会变成钱。行业实测中，传统手工录单单笔收银约 42–45 秒，流程优化后可降到 14–15 秒。开单是全天最密集的动作，任何效率提升都会被高频放大。（来源见文末 10）
  • 高峰流失直接对应挂单与提速。实测显示，高峰期因排队造成的客户流失可减少约 30%。门店真实情况是：一人多客、结到一半被叫走——没有挂单就只能重开或手写，两条路都指向漏单与更长的队。（来源见文末 10）
  • 三种「开不了单」是常态，不是例外。新客没建档、价目表没配全、收银被打断——旧流程会卡住；直接收款零前置兜住前两种，挂单兜住第三种。误操作率 14.2% 说明：路径越长，越容易在这些口子上漏钱。（来源见文末 11）

数据论证 · 为什么优先级高

  • 收益面最大、触发条件最少。开单是所有门店、所有员工、每天都要做的动作，改动收益不需要任何额外前提就会发生。相比之下，其他模块的收益需要门店先把配置做对。
  • 它是「免客服」能否成立的地基。如果开单还要靠教，后面每一个功能都要靠教；开单先变得不需要说明书，其他模块的自助率才有意义。
  • 风险最低、见效最快。不涉及存量数据迁移，功能链条短，可以独立上线、独立观测，是最适合先行推进的一段。
  • 行业数字化仍在渗透期，门槛就是竞争力。美发门店使用管理系统的比例从 2024 年的 40.9% 升到 2025 年的 47.3%，仍有超过一半门店没有系统。对这批门店来说，「上手要多久」往往比「功能有多全」更决定要不要用。（来源见文末 11）

门店场景

第三章

价目表 · 项目创建与管理把线上老价目表用顺、用透

Chapter 03

价目表不只是一个「价格清单」。开单能不能选到这个项目、会员卡的权益能不能覆盖、折扣的适用范围有多大， 全部由它定义。它是收银、权益、报表三条链路共同的价目地基。 这一章要做的，是把线上正在用的老版价目表更新成更好用的版本：看得更快、改得更少步、分组与排序能当经营抓手。

03

价目表 · 项目创建与管理

免客服 免销售 让门店业绩提升

一句话概括：把线上老价目表做透——找得到、改得快、推得动。 高密度列表让一屏扫到目标项，就地改价省掉跳页；自定义分组与拖拽排序，把「整理收纳」升级成「主推与营销」。

本模块能力条目（10 项）

  • 高密度信息行列表　一行即名称、时长 / 规格、价格，一屏能扫到更多条目，改价就在列表内就地展开。
  • 自定义分组 + 系统「隐藏」组　条目可多归属、可空组、删组不删货；「隐藏」组专门收纳对顾客端不可见的项。
  • 拖拽排序　在售 / 下架分桶内拖拽调整顺序并持久保存。排序即推荐位，是最省力的营销杠杆。
  • 在售 / 下架 / 隐藏 三态　给出跨端可见性矩阵：下架＝顾客端 / 开单 / 权益都不可选；隐藏＝仅顾客端不可见，开单仍可选。
  • 绑卡锁定 + 改价支付拦截　被会员卡引用的项目锁定关键属性（名称 / 预约 / 删除）；开单中改价触发支付前确认。
  • 与会员卡 / 开单联结　价目表是开单选品、会员卡选权益、折扣范围的同一份数据源；权益页可直达管理并能原路返回、自动刷新。
  • 主分组可改　承接统计与默认筛选的主分组允许调整，正面回应前线「大类选错不能改」的老痛点。
  • 变更轻提示　分组允许修改，只给 toast 轻提示，不弹确认窗、不阻断日常维护。
  • 即时生效、不回溯已结账　分组变更即时作用于之后的单据；已结清账目不因改组被悄悄重算。
  • 会员卡权益锚定主分组　卡权益按主分组对齐，避免自定义组增删改名导致已售卡口径漂移。

一线反馈 · 本方案观测口径
  • 价目表决定三件事，任何一件出错都会向上传染。开单能不能选到这个项目、会员卡权益能不能覆盖、折扣适用范围有多大——三者共用同一份数据。线上老版一屏信息密度低、改价要跳页，店主越不敢动、分类越失真，错位越容易出现。
  • 维护效率本身就是经营成本。场景测算里，月初调三个项目价格可从约 10 分钟压到约 3 分钟：高密度列表扫一眼定位，就地展开改完即生效。价目是每天都会碰的地基，慢一点就会被高频放大。
  • 分组与排序不是「整理癖」，是营销动作。把护理建成「夏季主推」组、拖到列表前排，再配更高提成，店员自然愿意推——排序即推荐位，分组即经营抓手，客单和毛利可以同向走。
  • 一线已经先给出了反馈。「大类选错不能改」不只是不方便，而是店主不敢动分组、报表维度长期失真。新的主分组可改、删组不丢货、变更只 toast，是对这个老痛点的正面回应——不是另起炉灶做跨平台搬家，而是把正在用的价目表做透。

数据论证 · 为什么优先级高

  • 它是收银与权益的共用地基，改一次、三条链路一起受益。开单选品、卡权益、折扣范围都读价目表；列表与分组用顺了，后面模块少踩「选得到 / 选不到」的坑。
  • 收益面大、不依赖额外培训。高密度列表、就地改价、拖拽排序都是「打开就会」的动作，符合「免客服」——店主自己就能把价目表维护成经营工具。
  • 它直接决定「该推的项目推不推得动」。没有可改的分组与可拖的排序，主推只能靠口头交代；写进系统之后，提成规则才挂得住、店员才有动力推。
  • 与提成规则同批对齐，避免「改了没反应」。分组模型与提成命中挂在同一套结构上；价目侧先理顺，提成侧的优先级链才站得住。

门店场景

月初调价 店主早上想调三个项目的价格。旧列表一屏只能看几条，来回滑半天还容易点错；新列表一屏扫到目标， 点开就地展开修改、保存即生效。三分钟做完原本要十分钟的事。
用分组做营销 店主把新上的一批护理项目建成「夏季主推」组，给这个组配一条更高的提成规则，店员推它就有额外收益； 同时把仪器类项目归入「高客单」组，前台一眼看到该往哪个方向推。 分组从「整理收纳」变成了「经营动作」，客单和毛利一起往上走。
大类选错能改 入驻时把「儿童剪发」归错了类。旧版大类选错不能改，只能将错就错或找客服；新版主分组可改、删组不丢货， 店主自己改完继续营业，不用为一次归类错误养一套长期失真的报表。

第四章

提成设置 · 多方案决定店员愿不愿意卖

Chapter 04

提成是门店里最敏感的一张表。算得清，店员就敢冲；算不清，再好的功能也推不动。 旧模型是「阶梯比例单方案 + 依赖业绩设置」，配置链路长、职责混叠， 店主既表达不了「不同分类、不同支付方式、不同工位」的差异化，也说不清为什么某个店员拿的是这个数。 这一模块的目标，是把这张表变成店主能自己配、店员能自己看懂的规则。

04

提成设置 · 多方案

免客服 免销售 让门店业绩提升

一句话概括：让店员相信「我该拿多少，系统算得对」，让店主敢改规则。 规则要能表达真实的分工（岗位、工位、顾客指定），也要能被看懂、被修正、被追溯。

本模块能力条目（6 项）

  • 多方案 + 一人多方案 + 同行取高　一套规则就是一个提成方案，可命名、可复制、可整方案分配员工；同一订单行命中多个方案时取金额更高者。
  • 规则块化：5 项默认 + 覆盖规则项　项目 / 产品 / 办卡 / 充卡 / 快捷开单 5 项默认规则，需要精细化时再叠加覆盖项（可整类分组或指定项目）。
  • 按工位分配 + 顾客指定提成　大 / 中 / 小工各自设提成；「顾客指定」可选开启，并叠加在原提成之上另计一笔。
  • 计算基数独立　每条规则自己决定按原价还是实收计算，不再经过旧「业绩设置」，配置链路显著变短。
  • 业绩只读解耦 + 流水提成可改留痕　业绩按原价加总、只读、不参与提成；提成可由店主 / 合伙人 / 店长修正，且改动留痕可审计。
  • 试算与「未分配」提示　方案保存前可试算；列表常驻提示「还有 N 人未分配任何提成方案」。

  • 流动率高，规则必须让新人一进店就挂得上、算得清。美业相关行业人员流动率约 41%。新人入职忘了分配方案、规则改了「没反应」、发薪日为一笔提成争论——这三件事最容易积累怨气。多方案 +「未分配」提示 + 流水可改留痕，就是把私下协调变成系统内可审计的动作。（来源见文末 11）

数据论证 · 为什么优先级高

  • 它与价目分组结构同批对齐，避免「改了没反应」。提成命中规则挂在分组上；价目侧分组理顺、提成侧优先级链一起上，店主才不会先经历一次「规则改了还是没反应」——那是最伤信任的一种体验。
  • 敏感度最高，错一次的成本远高于其他模块。工资是门店里唯一会被逐笔核对的数字。其他模块出问题影响效率，提成出问题影响的是店员对门店的信任，而信任的修复成本更高。
  • 它直接影响留存与招人成本。分成说不清是技师流失的直接原因之一；行业离职率已经在 16.5% 的高位，而招人与培养一个新技师的成本，远高于把规则一次配清楚。
  • 它是「让门店业绩提升」的最后一环。前面几个模块把单收进来、把项目理顺，最终要靠提成把「该推的项目推得动」——按工位、按顾客指定的差异化规则，才是把激励写进系统而不是靠店长拍脑袋。
