交付 01 让门店看见「新客是系统带来的」 锚定 · 帮门店赚钱 今天 17:00
一句话描述 · 问题 + 假设 + 方法 + 验证逻辑

问题：已购未开单门店中，一类反馈「功能齐全但日常用不到」、唯一诉求是有效拓客（门店 A），另一类明确想用却被录入成本卡住（门店 B），且门店 B 主动提出抖音团购核销需求； 假设：对前者而言，不用系统的真实原因不是功能缺失，而是「用了也看不到生意变化」——若让新客来源变得可见，使用动机就会从「替代手写」转为「带来生意」； 方法：把团购核销与会员建档串成一条「线上新客台账」——核销即自动开单、核销时可当场建档会员、复购可追踪； 验证：上线后该批门店核销订单占比自 0 起量、核销带入的新增会员数大于 0，且原「未首单」门店出现首单。

问题
  • 样本一（门店 A · 美时美刻皮肤管理中心）：肯定系统功能齐全，但「很多功能日常用不到」；不用的两条原因是① 没有吸引她的抓手、② 习惯手写（店内计算偏灵活、无固定规则）；唯一主动说出的价值锚点是「如果能有效拓客，我会考虑使用」。
  • 样本二（门店 B · 精剪坊形象工作室）：并非不想用，明确表示后面会正式使用；当前卡在老系统会员数据无法快速迁移、只能手动录入；主动提出有抖音团购的核销需求；最看重会员卡系统功能。
  • 样本三（门店 C · 梵诗专业设计烫染）：明确认为 SaaS 最重要的功能是记账，但实际因不习惯手机记账而总忘记用；根因是没有自主需求——本次购买来自亲戚推荐，老板自己当时并无主动购买意愿；同样有拓客需求；目前在美团有团购，为美团侧核销提供调研依据。
  • 三家合并看：不用系统的原因不止一类——门店 A 属价值感知缺失（看不到生意变化），门店 B 属迁移成本（想用但搬不进来，已单列为交付 02），门店 C 属无自主需求（购买来自外部推荐，从未为系统准备过理由，单独记录）。本方案锚定门店 A，并以门店 C 佐证「拉力来自能赚钱的功能」。
  • 一个跨样本共性 · 2 人小店：门店 A 与门店 C 均为 2 人小店（门店 B 为 3 人）。两家 2 人店都出现了「用不起来」的问题——A 是「手写更灵活」，C 是「总忘记用」。在老板兼店员、没有专人管流程的店里，任何依赖「店员记得主动操作」的设计都会被放大成门槛。这应是方案的一个硬约束，而非个别现象。
  • 数据侧佐证：门店 A 在经营看板仍为「未首单」；19 家圈选门店的团购核销订单基线为 0（能力未上线）；看板口径明确「网上已付款订单是另一套账，绝不与店内收银加总」——线上客流今天完全在剑琅账外。
假设
  • 主因判断：门店 A 这类门店不用系统，不是因为功能不够，而是因为用了也看不到生意变化——功能的价值与店主的收益之间缺少一条可见的因果链。
  • 推论：若把「系统带来了新客」变成门店能自己看见的结果，使用动机就会自然迁移，不需要靠说服。
  • 「刚需 ≠ 拉力」（门店 C 提供的佐证）：门店 C 明确说「记账最重要」，行为上却总忘记用——说明核心刚需本身不构成打开系统的理由。而三家主动说出的诉求（门店 A 要拓客、门店 B 要抖音核销、门店 C 要拓客）指向的都是能赚钱的功能。这强化了本方案锚定「帮门店赚钱」而非「替代手写」的判断。
  • 门店 B 对假设的修正：它的阻碍不是价值判断，而是迁移成本，本方案的假设对它不成立。这条已单列为交付 02，避免用一套假设覆盖所有门店。
  • 门店 C 对假设的修正：它的阻碍是缺少自主需求（被动购买，用不起来），同样不由本方案覆盖，已单独记录。
方法
  • 主线 · 串成一条「线上新客台账」：团购核销 → 核销自动开单 → 核销时确认散客 / 会员并可当场建档 → 门店可查「线上券带来的新客与复购」。即：把平台买来的客，变成门店自己的会员。
  • 需求侧已被验证 · 且双平台各有实证：抖音侧——门店 B 主动提出抖音团购核销需求；美团侧——门店 C 已在做美团团购。团购核销是抖音 + 美团双平台能力，而两个平台各自都有门店实证支撑，说明这不是单一平台的偶发诉求，上线后有现成的使用动机，不需要额外教育。
  • 配套 · 降低上手门槛（回应门店 A 的「手写更灵活」）：价目表主分组可改、删组不丢货、列表内就地改价；提成支持多方案与覆盖规则，并允许流水级修正且留痕。
  • 前提约束 · 面向 2 人小店设计：本次样本中门店 A（2 人）与门店 C（2 人）都出现「用不起来」，说明小店没有专人管流程。因此方案不能依赖「店员记得主动操作」，要么把动作压在核销这一步（顺手动、不额外增加步骤），要么让结果自动呈现到门店能看到的地方。
  • 呈现：在门店可见处只给两个数——核销订单占比与核销带入的新增会员数。
验证
  • 主验证：该批未使用门店的「未首单 → 有首单」转化（经营看板健康状态）；门店 B 表现出的使用意愿最强，可优先观察它迁移完成后是否真正用起来。
  • 过程指标：核销订单占比 / 核销订单金额占比自 0 起量；核销带入的新增会员数大于 0。
  • 反向证伪：若核销占比已起量、门店仍不使用，说明「可见的生意结果」还不足以驱动使用，假设需修正——届时改锚定「免客服」链路（问题转为上手与配置成本）。
  • 主观验证：回访确认门店是否主动提及「新客」，并表现出继续使用的意愿。
交付 02 让门店的会员数据能自己搬进来 锚定 · 免客服 明天 17:00
一句话描述 · 问题 + 假设 + 方法 + 验证逻辑

问题：门店 B 明确想用剑琅联盟，却因老系统会员数据无法快速迁移、只能手动录入，一直未能投入使用； 假设：门店的上线阻碍不止「看不到价值」，还有「搬不进来」——当会员存量是门店最看重的资产时，迁移成本会直接变成一个硬门槛，卡住原本有意愿的门店； 方法：为会员/客户档案提供可自助完成的批量导入（模板导入 + 校验与错误回执），把「人工逐条录入」变成「一次导入、分批校对」，必要时配套代录支持通道； 验证：上线后该批门店的会员档案数出现台阶式增长、手动录入相关咨询/工单量下降，且门店 B 完成迁移后进入正式日常使用。

问题
  • 样本（门店 B · 精剪坊形象工作室）：并非不想用，明确表示后面会正式使用；当前卡在老系统的会员数据无法快速迁移、只能手动录入，因此会员卡还没全部录进去，也就一直没投入使用。
  • 该店最看重会员卡系统功能——即：它最想要的那块能力，恰恰被迁移成本挡在最前面。
  • 这不是个例性抱怨，而是会员型门店的通用门槛：只要是已有存量的门店，第一件事都是把老会员搬进来。
假设
  • 主因判断：门店不用系统的原因不止一类。交付 01 处理的是「看不到价值」；这一类是「想用但搬不进来」——阻碍在迁移成本，而非价值判断。
  • 推论：对已有会员存量的门店，迁移成本是上线的前置门槛。跨不过这道门，后面所有功能都用不起来——哪怕门店本身有意愿。
  • 价格变量已排除：门店 B 明确认为我们的定价有价格优势。卡住它的不是「值不值」，而是「搬不搬得进来」——这排除了性价比解释，让「迁移成本」这条假设更干净。
  • 为什么归入「免客服」：手动逐条录入是典型的「需要人帮忙才能完成」的动作。让它变成门店自助可完成，正是「免客服」要消灭的那类成本。
方法
  • 主线 · 让迁移自助化：提供会员 / 客户档案的批量导入（模板下载 → 填充 → 导入 → 校验与错误回执），把「逐条手录」换成「一次导入、分批校对」。
  • 兜底：对确实无法自助导出的老系统，保留代录支持通道（由服务侧承接），让这类门店不至于完全卡死。
  • 配套：导入后给出清晰的成功 / 失败条数与原因，让门店能自己判断还差什么、而不是反复来问。
  • 优先级判断：绑定在会员卡上线之前完成——会员卡是该批门店最看重的功能，迁移是它的前置条件。
验证
  • 主验证：门店 B 完成会员迁移并进入正式日常使用（出现持续、真实的收银记录，而非测试性单据）。
  • 过程指标：该批门店的会员档案数量台阶式增长；手动录入 / 迁移相关的咨询与工单量下降。
  • 反向证伪：若迁移通道已提供、门店仍未开始使用，则说明真实阻碍另有他因（例如规则复杂度或人员意愿），假设需重新归类。
